# EchoVision — AI Voice Navigation Assistant for the Visually Impaired
### Phase 1 — Desktop / VS Code Prototype

Real-time object detection (daily-life objects **and** navigation hazards),
monocular distance estimation, left/center/right direction detection, and
spoken guidance — running entirely offline on your laptop webcam.

---

## 1. What detects what (and why no paid "API" is used)

There is no external object-detection **service** here (no Google Vision,
AWS Rekognition, Azure CV, etc.) — those cost money, need internet, and add
latency, which is the opposite of what a real-time mobile safety aid needs.
Instead, EchoVision runs **two open-source YOLOv8 models fully offline**:

| Model | Classes | Covers |
|---|---|---|
| `models/yolov8n.pt` (auto-downloaded) | **COCO — 80 classes** | *"objects we see in daily life"*: person, bicycle, car, motorcycle, bus, truck, chair, bench, dining table, laptop, bottle, backpack, dog, cat, suitcase, traffic light, stop sign, and 65 more. This is the same open COCO dataset/model referenced in your brief ("COCO dataset") — Ultralytics ships it pretrained, so no manual download or API key is needed. |
| `models/navigation_best.pt` (you train it — see §5) | **9 custom navigation-hazard classes** | stairs, pothole, speed_breaker, open_drain, road_barrier, construction_block, traffic_cone, curb, low_hanging_obstacle |

Both are Ultralytics YOLOv8 — MIT-style AGPL open-source, run locally,
no rate limits, no internet required after the first download.

> **On "open APIs":** if you specifically want to compare against a hosted
> API later (e.g. for a report), Roboflow's free-tier Inference API or
> Google's on-device ML Kit Object Detection are open/free options — but
> neither is required, faster, or more accurate than the local YOLOv8
> models already wired in here, so this project does not depend on them.

## 2. Low-light handling (honest description)

`src/utils.py::enhance_low_light()` runs automatically before every
detection pass:
1. Measures mean frame brightness.
2. If it's below `LOW_LIGHT_BRIGHTNESS_THRESHOLD` (config.py), applies
   **CLAHE** (adaptive local-contrast enhancement) on the LAB L-channel.
3. If it's *very* dark, additionally applies **gamma correction** to lift
   shadow detail.

This measurably improves YOLO's recall in dim/dusk/indoor conditions.
**It cannot invent detail a camera sensor never captured** — for genuinely
low-light-critical deployment (e.g. night navigation), the honest next step
is a phone camera's hardware night mode or an IR-assisted sensor, wired in
at the Phase-2 Android layer. This is documented here rather than glossed
over so you know exactly what the software is and isn't doing.

## 3. Distance estimation (honest description)

`src/depth_estimator.py` uses **MiDaS-small** (monocular depth, open-source,
`intel-isl/MiDaS` via `torch.hub`) to estimate *relative* depth, then
converts it to an approximate metre figure using a calibration constant
(`DEPTH_SCALE` in `config.py`).

**A single RGB camera cannot produce lab-accurate metric distance** — that
needs either a known reference object in frame, a stereo camera, or a depth
sensor (LiDAR/ToF). What this project gives you is a **calibrated estimate**
good enough for "close / medium / far" navigation guidance, and a
`calibrate_scale()` helper in `depth_estimator.py` so you can tune it
against one real, measured distance (place an object exactly 2 m away,
run calibration, update `DEPTH_SCALE`). For survey-grade accuracy, the
correct upgrade path is a LiDAR/ToF-equipped phone via ARKit/ARCore depth
APIs in the Phase-2 Android app — flagged clearly so this isn't oversold.

## 5. Setup

```bash
# Open the EchoVision folder in VS Code, then in its integrated terminal:

python -m venv venv
venv\Scripts\activate        # Windows
source venv/bin/activate     # macOS/Linux

pip install --upgrade pip
pip install -r requirements.txt
```

Python 3.9–3.11 recommended. A CPU is fine for the demo; an NVIDIA GPU
speeds up both inference and training.

## 6. Running the app

### Quickstart — general objects only (no custom training needed)

```bash
python main.py
```

```bash
python main.py --source 0              # default webcam
python main.py --source 1              # second camera
python main.py --source path/to.mp4    # run on a video file
python main.py --save                  # save annotated video → outputs/recordings/
python main.py --no-tts                # silent mode
python main.py --no-low-light-boost    # disable auto low-light enhancement
python main.py --no-depth              # skip MiDaS (faster, no distances)
```

Press **ESC** in the video window to stop.

### Run the test suite

```bash
pytest tests/
```

## 7. Training the custom navigation-hazard model (stairs, potholes, etc.)

I can't download copyrighted/licensed image datasets into this package for
you automatically — but here are real, **open, free** sources for each
class (see full list + links in `training/prepare_dataset.py`'s docstring):

| Class | Open dataset source |
|---|---|
| pothole | Kaggle: `atulyakumar98/pothole-detection-dataset` |
| stairs, speed_breaker, open_drain, road_barrier, construction_block, traffic_cone, curb, low_hanging_obstacle | [Roboflow Universe](https://universe.roboflow.com) — search each term, export any public dataset in **"YOLOv8"** format |

```bash
# 1. For each class, extract the downloaded export into:
#      datasets/navigation_dataset/<class_name>/images/*.jpg
#      datasets/navigation_dataset/<class_name>/labels/*.txt
#    (Roboflow YOLOv8 exports already look like this)

# 2. Merge all classes into one unified multi-class dataset (80/20 split)
python training/prepare_dataset.py

# 3. Train (fine-tunes yolov8n.pt on your 9 hazard classes)
python training/train.py --epochs 100 --batch 16 --device cpu
# use --device 0 if you have an NVIDIA GPU

# 4. Evaluate
python training/evaluate.py

# 5. Run the full app — navigation_best.pt is now picked up automatically
python main.py
```

You don't need all 9 classes labelled to get value — `prepare_dataset.py`
happily trains on however many classes you've populated; missing classes
are just skipped with a `[skip]` message.

## 10. Honesty summary (what this can and can't promise)

- ✅ Detects 80 everyday COCO objects + up to 9 custom navigation hazards, fully offline.
- ✅ Auto-enhances dim frames to help detection in low light.
- ✅ Gives calibrated, useful *relative* distance guidance (near/medium/far).
- ✅ Announces left/center/right direction and speaks natural sentences.
- ⚠️ Not lab-accurate metric distance from a single camera — calibrate `DEPTH_SCALE` for your setup, or add a depth sensor for survey-grade numbers.
- ⚠️ Low-light enhancement helps but has physical limits — true night use needs a night-capable sensor.
- ⚠️ The 9 hazard classes require you to supply/label training images — no bundled dataset ships in this zip (mostly due to per-source licensing), but free open sources are linked above.
